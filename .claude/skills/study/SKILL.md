# /study

주제: $ARGUMENTS

사용자가 이 설명을 읽고 **직접** 노트를 쓴다. 노트 파일을 만들거나 대신 쓰지 않는다. 채팅으로만 설명한다.

## 설명 형식

1. **한 줄 정의 + 비유**: 처음 보는 사람도 감이 오게.
2. **핵심 개념**: 소제목으로 나눠 기초부터 쌓는다. 앞 개념이 뒤 개념의 근거가 되도록 순서를 잡는다.
3. **구조 그림 / 비교 표**: 구조는 코드블록 그림, 비교는 표로.
4. **실무 연결**: 서버 운영·백엔드 개발에서 이 개념이 어디서 문제로 드러나는지 (증상, 확인 명령어, 로그).
5. **스스로 확인해 볼 질문**: 5~7개. 안 보고 답할 수 있는지 확인하는 질문. 답은 주지 않는다.
6. **노트 위치 추천**: 레포 폴더 중 어디에 어떤 파일명(`kebab-case.md`)으로 둘지 한 줄. 여러 분야에 걸치면 나눠 둘 곳도 제안.

## 규칙

- 정확성 우선. 확실하지 않은 수치·동작은 "대략", "보통"으로 범위를 밝힌다.
- 주제가 넓으면 기초 범위로 좁혀 설명하고, 이어서 볼 하위 주제를 마지막에 한 줄로 제안한다.
- 레포 폴더: `cs/network`, `cs/os`, `cs/database`, `cs/data-structure-algorithm`, `backend`, `ai`, `certificate`
